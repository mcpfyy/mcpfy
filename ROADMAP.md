## 🔭 Up Next

In build order:

1. [ ] **Skill to build your MCP** - a Claude Code Skill (and equivalents for other agents) that scaffolds, writes tools, and iterates on a full server from a plain-language description - no hand-written boilerplate
2. [ ] **`mcpfy-pulse` SDK** - drop-in telemetry for any MCP server: call counts, latency, error rates, and tool usage, with zero code changes if you're already on `mcpfy-sdk`
3. [ ] **MCP v2 support** - day-one compatibility once the next major revision of the spec lands, with a migration path that doesn't break existing `mcpfy-sdk` servers
4. [ ] **CLI to deploy on MCP Cloud** - `mcpfy deploy`, one command to push a local project straight to MCPFY's hosted infrastructure - auth, custom domains, and OAuth already wired up
5. [ ] **Deploy to your own server** - the same CLI, pointed at a Docker image, a VPS, or your own cloud, for teams that need to self-host
6. [ ] **CLIfy** - turn an existing API into a standalone CLI tool, using the same spec-parsing pipeline that already turns a curl command into an MCP server
7. [ ] **Python SDK** - same ergonomics as the TypeScript SDK: tools, prompts, resources, widgets
8. [ ] **Go SDK** - same, for Go
